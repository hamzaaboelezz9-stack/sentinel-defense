# Seven-minute engineering presentation
0:00–1:00: Explain the fictional assets, data schema, and trust boundaries. “This is a defensive educational simulation, not a military system.”
1:00–2:00: Generate normal logs, then a brute-force sequence. These operations create records and never contact external targets.
2:00–3:00: Inspect the five-in-sixty-seconds rule, matching evidence IDs, and idempotent ingestion. Explain fixed-bucket deduplication's boundary limitation.
3:00–4:00: Run the connected laboratory. Explain independent training/calibration/evaluation splits and how synthetic distribution choices influence results. Do not call an anomaly proof of attack.
4:00–5:00: Save assignment, status, and findings. Show the analyst history and viewer API restrictions.
5:00–6:00: Review response recommendations and benign alternatives. Explain why no account disabling or blocking can execute.
6:00–7:00: Export the briefing. Explain the test evidence, architecture compromises, and work needed before operational use.

Use Engineering demo to follow these stages. The presenter advances manually; the software does not pretend to have delivered a timed operational incident.
